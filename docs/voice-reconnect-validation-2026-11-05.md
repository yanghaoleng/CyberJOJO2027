# 语音连接恢复验证（2026-11-05，本地）

## 范围和状态

本轮在已发布的 `d417b7a6c63a968ad39dff500570d5fa7493af33` 上继续做本地改进。新增语音稳定性改动基于此版本实施；用户已明确确认推送和部署。线上90条事件库内容保持不变。

用户故事：打开相机并开启语音 → 浏览器收音与 WebSocket → 现有语音桥接和模型 → 恢复或可见的故障状态；可恢复错误持续重试，主动关闭和明确停止后不自动开麦。

## 已定位和修正

- 过去在每次 ready 后立即重置退避，反复短连会持续从短延迟重试；现在仅连续稳定30秒后清零。
- 断网或后台期间仍消耗重试次数，并可能在恢复时等待旧计时器；现在暂停计时，网络或前台恢复时唤醒。
- 多处调度分散在闭包，难以验证取消；现在每个相机实例只有一个恢复状态机、一个退避计时器，退出和主动关闭会取消所有待恢复动作。
- 收音初始化等待 AudioContext.resume 可能长期挂起；增加6秒上限、退出取消和资源释放。设备/权限/服务鉴权错误独立阻塞，不反复申请麦克风或无效重试。
- 用常驻小提示显示连接中、倒计时、等待网络/前台以及权限/设备操作；恢复即消失。明确的关闭按钮和菜单入口不与玩法退出混用。
- 初始化测试发现浏览器原生计时器需要保持全局接收者，已修正并添加回归；提示安全区变量缺省时补默认值，已确认提示位于画面内。

这些是可以从代码和隔离验证确认的恢复机制缺陷；不把它们推断成所有真实设备断连的唯一根因。网络、系统音频中断及上游服务超时仍可能发生，新的恢复机制用于处理这些情况。

## 浏览器证据（隔离假设备、模拟连接）

已用真实 App 组件和模拟 WebSocket / 假音视频在浏览器操作，不访问真实摄像头或麦克风：

- 断网后提示持续显示，恢复网络后自动连接并移除提示。后台断开显示等待前台，回前台恢复。
- 连续不返回 ready 导致多次12秒就绪超时并退避；观察到连接计数从1增长到6，活动连接始终最多1、媒体申请仍为1、开场仍为1。手动立即重试后成功且没有重播。
- 模拟鉴权错误后提示“语音服务授权不可用，请联系维护者”，关闭连接；触发断网/恢复后仍不重试。
- 主动关闭、菜单手动开启、明确“关闭语音”分别生效；明确停止后再触发网络恢复，没有新连接或麦克风申请。
- 初始拒绝麦克风时回退到相机和文字入口，同时常驻权限提示；网络恢复不再申请麦克风。用户修复权限并主动点击恢复后才重新申请并连接。
- 模拟 pagehide 后，再触发网络恢复，活动连接为0、连接数与媒体申请数不增加。

上述过程中未观察到重复开场或多个活动连接。音频播放取消继续复用已有流代次/队列清理机制；物理扬声器、手机系统与儿童真机未验收，不将模拟检查称为真实设备验收。
