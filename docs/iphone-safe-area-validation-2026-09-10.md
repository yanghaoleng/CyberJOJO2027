# iPhone 安全区兼容验证 · 2026-09-10

## 修改

- 全屏页面共用 `env(safe-area-inset-*, 0px)`，随旋转更新，不按机型猜测尺寸。
- 封面入口独立于可滚动内容，位于顶部安全区下方；主操作和说明避开底部横条，短横屏可滚动。
- 资源和日志页面四边留白，资源吸顶栏保持在安全区下方。白底页面给主屏幕应用的浅色状态文字保留深色背景。
- 玩具名片弹窗按四边安全区限制高度；已避让的相机取景框内部不重复扣除顶部安全区。横屏玩法菜单可滚动。
- 触屏表单使用 16px 字号，减少 iOS 聚焦自动缩放；主屏幕图标采用根路径，子页面添加到桌面时也能正确找到。

## 验证

通过 Chrome DevTools `Emulation.setSafeAreaInsetsOverride` 覆盖浏览器实际 CSS 环境变量，没有修改页面的安全区自定义变量。封面、资源页、日志页分别验证以下 6 组尺寸，共 18 组：

| 视口 | 上 / 右 / 下 / 左安全区 |
| --- | --- |
| 393 × 852 | 59 / 0 / 34 / 0 |
| 375 × 812 | 44 / 0 / 34 / 0 |
| 320 × 568 | 20 / 0 / 0 / 0 |
| 852 × 393 | 0 / 59 / 21 / 59 |
| 932 × 430 | 0 / 59 / 21 / 59 |
| 390 × 844 | 0 / 0 / 0 / 0 |

检查通过：入口可命中且滚动后位置稳定，页头和页尾安全，资源栏吸顶安全，无横向溢出。使用虚拟摄像头另验证相机顶部按钮、快门、作品入口、玩法菜单和名片弹窗的横竖屏布局，以及横屏作品列表。

`npm test`：120 项通过。`npm run build`：通过。

这是浏览器布局模拟，不是 iPhone 真机或 iOS 主屏幕容器实测。没有改动设备权限、语音服务或相册数据。

参考：[WebKit 安全区布局](https://webkit.org/blog/7929/designing-websites-for-iphone-x/)、[Chrome DevTools 安全区模拟](https://chromedevtools.github.io/devtools-protocol/tot/Emulation/#method-setSafeAreaInsetsOverride)。
